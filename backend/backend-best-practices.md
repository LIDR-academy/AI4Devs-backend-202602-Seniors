# 🛠 Backend Best Practices

## 1. Hexagonal Architecture: The "Core" is Sacred

To prevent code from becoming a "technical debt factory," we must separate business logic from external tools.

### Isolation of Express

Express is merely an entry Adapter. Your route logic must immediately delegate to a Use Case or Domain Service. Do not pass `req` or `res` objects beyond the controller.

### Isolation of Prisma

Prisma is a persistence Adapter. The domain should not know the types generated by `prisma.schema`. Define your own Entities and use the Repository pattern to mediate between the Core and Prisma.

### Ports (Interfaces)

Define interfaces in TypeScript for your repositories and external services. This allows you to swap Prisma for another tool or use fakes in tests effortlessly.

## 2. Domain Modeling (DDD) in TypeScript

A backend with clear boundaries produces more predictable AI agents.

### Value Objects

Use classes for data with its own validation (e.g., Email, Price, OrderId). Make them immutable and self-validating in the constructor.

### Entities and Aggregates

Do not create anemic models (data-only). Business rules (invariants) should live within the entities themselves.

**Example:** If an order cannot add items after being paid, that `if` should be in the `addItem()` method of the `Order` class, not in the Express controller.

### Ubiquitous Language

Use names in the code that reflect the business (e.g., `placeOrder` instead of `createOrderRecord`) so that AI does not invent terms.

## 3. Design Principles for the "AI Era"

### SOLID and CUPID

**D - Dependency Inversion:** Inject your Prisma repositories into services through their constructors. This greatly facilitates automatic test generation by AI.

**D - Domain-Based (CUPID):** Organize your folders by business modules (e.g., `src/modules/billing/`) instead of technical folders like `controllers/` or `models/`. This creates "context units" that fit within the AI window.

### Error Handling

**Result / Either Type:** Avoid overusing exceptions (try/catch) for business logic. Use types that represent success or failure so the flow is explicit and typed in TypeScript.

## 4. Specific Patterns and Practices

### Repository Pattern

Create interfaces that return complete Aggregates. Prisma should be an implementation detail within the class that implements that interface.

### Factory

Use it to instantiate complex objects or choose between different service providers (e.g., `PaymentProviderFactory`).

### Avoid Singletons

Do not use Singletons for your services or database clients; they break testability and horizontal scaling. Use a Dependency Injection container or manual composition.
